# Luckysheet 可嵌入式 Spreadsheet UI SDK 改造方案

## 1. 目标与交付边界

本项目继续以 Luckysheet 的开源代码为基础维护，不迁移到 Univer。核心诉求是保留已有表格能力和数据资产，掌握源码、构建、发布和扩展能力，降低宿主项目的接入及长期维护成本。

产品定位是 **Spreadsheet UI SDK**：可嵌入业务页面、带有完整表格交互的 SDK。Vue、React 等组件是接入层，表格业务逻辑由框架无关的 SDK 统一提供。

本文以原方案中已经明确的目标为约束；以下版本划分、接口草案和测试规模是实施建议，不表示功能已经实现，也不代表已经测得的性能。现状依据当前仓库代码核对，不以旧 README 中的功能宣传作为验收证据。

### 1.1 目标到验收的对应关系

| 目标                          | 可检查的交付结果                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------------------- |
| 持续自主维护 Luckysheet       | 源码和依赖可追溯，固定依赖后可构建；基础编辑、公式和保存不要求外部在线服务                |
| 嵌入不同技术栈                | 原生 Web 可直接接入；Vue、React、Angular 和 Web Component 通过同一公开 API 接入，分批交付 |
| 保留类似 Excel 的核心体验     | 编辑、公式、格式、复制粘贴、撤销重做、合并、冻结、筛选、排序等通过回归用例                |
| 多个实例相互独立              | 同页 A、B 的数据、公式、选区、历史、语言、主题和销毁互不干扰                              |
| 支持主题、功能开关和自定义 UI | 同页使用不同主题；隐藏内置工具栏后，宿主按钮仍可调用相同命令；禁用能力有一致行为          |
| 可扩展高级能力                | 插件仅通过公开上下文工作，能够按需加载、释放资源并保存自己的数据                          |
| 稳定 API 和数据兼容           | 提供类型、契约测试、版本说明和旧数据转换；宿主不读取内部 Store 或控制器                   |

### 1.2 首个可用版本与长期范围

首个可嵌入版本必须完成：原生接入、真实多实例、完整生命周期、P0 表格能力、版本化快照、基础主题和公开 API。只有单实例兼容封装时，版本应标记为实验性，不能宣称完成 SDK 改造。

多框架适配和高级插件在此基础上逐项发布。优先完成原生示例及 Vue、React 适配，再补齐 Angular、Web Component；它们都属于长期目标，不能因目录规划遗漏而被取消。

当前不将以下事项作为首个版本的前置条件：完整复刻 Excel、VBA/宏、全部 XLSX 特性无损往返、服务端表格渲染、移动端完整编辑、协同服务端、全面 TypeScript 迁移、全面移除 jQuery、重写 Canvas 渲染器。遇到不支持的数据或功能，应报告具体限制并保护原数据。

## 2. 当前仓库评估

### 2.1 构建产物与包入口不一致

[package.json](../package.json) 声明了 CJS、ESM 和浏览器入口，但 [gulpfile.js](../gulpfile.js) 的默认 `build` 调用 `core()`，该函数使用 esbuild 生成 IIFE，输出名为 `dist/luckysheet.umd.js`。文件名不能证明它是 UMD。

文件中另有生成 UMD/ESM 的 `core_rollup()`，但它没有接入默认构建任务；默认构建也未生成声明的 CJS 文件。因此不能沿用“仓库目前可以生成 ESM 和 UMD，所以已具备模块接入能力”的判断。需要检查干净构建、实际导入和安装包内容，不能依赖仓库中已有的 `dist` 文件。

[src/index.js](../src/index.js) 在模块顶层读取 `window` 和 `navigator`。新入口需要支持在无 DOM 的环境中安全导入，实际创建和渲染仍只在浏览器发生。

### 2.2 单例不只有 Store

[src/store/index.js](../src/store/index.js) 导出全局可变对象；[src/core.js](../src/core.js) 的 `create()` 首先调用全局 `method.destroy()`，创建 B 会清理 A。

其他需要纳入实例化的状态至少包括：

| 位置                                                           | 已发现的共享状态或依赖                                      | 改造方向                       |
| -------------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------ |
| [配置控制器](../src/controllers/luckysheetConfigsetting.js)    | 工具栏、权限、钩子等运行配置                                | 每实例配置对象                 |
| [公式模块](../src/global/formula.js)                           | 模块对象中的计算状态、`window.luckysheet*` 辅助函数和缓存   | 实例公式服务及显式计算上下文   |
| [工作表管理](../src/controllers/sheetmanage.js)                | 当前工作簿相关控制状态                                      | 实例工作表服务                 |
| [网络控制器](../src/controllers/server.js)                     | 地址、连接、重试定时器                                      | 实例网络服务和可取消任务       |
| [语言入口](../src/locale/locale.js)、[core.js](../src/core.js) | 语言读取全局 Store，日期控件调用全局 `flatpickr.localize()` | 按实例传入语言及第三方控件选项 |
| [销毁与默认配置](../src/global/method.js)                      | 集中重置公式、图片、透视表、冻结等模块                      | 资源所有权及各模块释放契约     |

这是一份起始清单，实施时还要登记模块级可变对象、缓存、第三方全局注册和异步回调。仅把 Store 改成工厂仍不足以支持多实例。

### 2.3 DOM、事件与生命周期没有实例边界

[src/global/method.js](../src/global/method.js) 的 `destroy()` 会清空容器，删除 `body` 下菜单、固定 ID 节点及 `.chartSetting`，并统一解绑 `document` 上的 `.luckysheetEvent` 和 `.luckysheetProtection`。

固定 ID、跨容器选择器和共享事件命名空间会导致实例互相影响。异步加载、定时器、观察器、网络重连及第三方控件也必须统一登记，不能只以容器 DOM 已被删除判断销毁完成。

### 2.4 Vue 封装和旧插件仍依赖全局环境

[integration/vue/Luckysheet.vue](../integration/vue/Luckysheet.vue) 虽然生成不同容器 ID，但返回的仍是全局 `window.luckysheet`。组件卸载时调用全局销毁，而且异步资源加载完成后可能在已卸载的组件中继续创建。

[luckysheet-loader.js](../integration/vue/luckysheet-loader.js) 使用页面级 Promise 缓存，按顺序注入 CSS、jQuery、第三方插件和主脚本。资源加载失败的重试、不同资源地址及版本共存也需要明确处理。

仓库已有 [expendPlugins 注册入口](../src/controllers/expendPlugins.js)，但不是完整的实例插件契约。[图表插件](../src/expendPlugins/chart/plugin.js) 包含从 unpkg 加载 Vue、Vuex、Element UI、ECharts 的地址，并向 `body` 挂载 UI。新增 `registerPlugin()` 方法不会自动解决这些依赖与隔离问题。

### 2.5 测试和数据执行边界需要补齐

当前 `package.json` 没有测试脚本，也未发现覆盖 SDK 生命周期、多实例和核心交互的系统性自动化测试。先建立可复现基线，再移动高耦合代码。

`core.js`、`controllers/sheetmanage.js`、`controllers/server.js` 等存在用 `new Function()` 解析数据的路径；`global/formula.js` 等还将其用于表达式计算。必须区分两类用途：远程或持久化数据应按明确 JSON 协议解析并校验；公式计算则需要单独迁移和回归，不能机械替换为 `JSON.parse()`。完成一处数据解析修复不等于整个 SDK 已支持禁止动态代码执行的 CSP。

## 3. 架构与迁移约束

```text
宿主应用：原生 Web / Vue / React / Angular / Web Component
                         │
                 公开 Spreadsheet SDK
              实例、命令、事件、快照、配置
                         │
                 SpreadsheetRuntime
       ┌─────────────────┼──────────────────┐
   Model / Formula   UI / Renderer     实例资源与服务
       └─────────────────┼──────────────────┘
                   PluginContext
             图表、透视表、文件、打印、协同
```

这是目标依赖关系，不要求第一轮拆成多个 npm 包。当前代码中公式、模型和 DOM 耦合较深，应先在现有目录建立接口边界，再考虑物理拆包。

### 3.1 实例运行时

```ts
// 目标接口草案；服务类型在对应模块迁移时补齐。
interface SpreadsheetRuntime {
  id: string;
  host: HTMLElement; // 宿主提供，SDK 不删除它
  root: HTMLElement; // SDK 创建并拥有
  overlayRoot: HTMLElement; // SDK 创建并拥有
  store: SpreadsheetStore;
  formula: FormulaService;
  commands: CommandManager;
  events: EventManager;
  resources: ResourceScope;
  plugins: PluginManager;
  signal: AbortSignal;
}
```

所有可变状态通过工厂创建；嵌套数组、对象、缓存和插件状态不能共享引用。只读函数表和不可变常量可以共享。控制器逐步改为接收 `runtime` 的函数或工厂，异步回调始终捕获所属实例。

禁止用一个全局 `activeStore` 在 A、B 之间切换来模拟实例化：定时器、公式回调、网络返回和重入调用都可能读取错误实例。焦点可以有当前活动实例，数据归属不能依赖焦点。

### 3.2 渐进迁移与旧入口

保留旧 `luckysheet.create/destroy` 的兼容入口，明确其单例语义。新入口先通过独立的 legacy bridge 调用旧实现，桥接阶段只允许一个活动或创建中的实例；第二次创建必须在调用旧 `create()` 前返回 `UNSUPPORTED_MULTI_INSTANCE`，保证第一个实例不被销毁。同一宿主重复创建返回 `CONTAINER_IN_USE`。

桥接阶段不能保证与绕过 bridge 的旧全局调用共存，接入说明必须禁止混用，并在可检测时提前报错。真正实例化完成后，旧 API 才可路由到专用默认实例，且旧 `destroy()` 只影响该实例；此时再验收新旧入口共存。

按“创建 → 数据 → 公式 → 渲染 → 编辑/历史 → 销毁”的完整调用链迁移。某条链路仍依赖全局状态时，维持实验性限制；允许分批合并代码，但不能提前开启多实例。每个迁移步骤保留回归用例和可回退的兼容路径，避免同时大规模搬目录、改构建和重写算法。

### 3.3 DOM、弹层和资源所有权

查询限定在 `runtime.root` 或 `runtime.overlayRoot`；内部节点优先用引用或 `data-role`，必须使用 ID 时包含实例前缀。事件解绑使用精确回调或每实例命名空间，禁止全局 `.off()` 和按通用类名清理页面节点。

弹层默认放在实例内。宿主有 `overflow` 裁剪、弹窗或全屏需求时，可配置 `overlayContainer`，但 SDK 只能在其下创建并删除自己的子节点；同步实例主题、语言、层级和焦点归属。不能对宿主容器执行 `replaceChildren()`。

资源管理器登记 DOM 事件、订阅、定时器、动画帧、观察器、请求、WebSocket、Worker 和第三方控件。销毁先标记终止并阻止新命令，再取消异步任务、按依赖逆序释放插件及控件，最后移除所属节点。单个释放回调失败不能阻止其他资源释放；重复销毁无副作用。

键盘和剪贴板需要页面监听时，由按 document 管理的路由器根据焦点、事件路径及弹层归属分发；最后一个实例销毁时释放共享监听。宿主输入框中的复制粘贴、快捷键和中文输入法不能被表格拦截。跨实例复制使用明确的剪贴板序列化，撤销历史仍各自独立。

## 4. 公开 API 契约

以下为目标 API 草案，包名中的 `@your-scope` 是占位符。每个预览版应列出已实现的子集；第一轮不允许用空实现伪装尚未具备的能力。

```ts
import { createSpreadsheet } from "@your-scope/spreadsheet";
import "@your-scope/spreadsheet/style.css";

const abortController = new AbortController();
const sheet = await createSpreadsheet(containerElement, {
  data: { format: "luckysheet", sheets: legacySheets },
  locale: "zh-CN",
  readonly: false,
  features: { filter: true, sort: true },
  ui: { toolbar: true, formulaBar: true, statusBar: true },
  theme: { colorPrimary: "#1677ff" },
  signal: abortController.signal,
});

const unsubscribe = sheet.on("workbook-change", event => {
  // 事件包含 revision、source 和受影响范围；按业务需要保存。
});

await sheet.setCellValue({ sheetId: "sheet-1", row: 0, column: 0 }, "hello");
await sheet.execute("sheet.set-cell-value", {
  target: { sheetId: "sheet-1", row: 1, column: 0 },
  value: { formula: "=A1" },
});

const snapshot = sheet.getSnapshot();
await sheet.load({ format: "snapshot", snapshot });
sheet.resize();
unsubscribe();
sheet.destroy();
```

### 4.1 地址、异步和错误约定

| 接口或行为                         | 目标约定                                                                                                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `createSpreadsheet(host, options)` | 返回 Promise；数据校验、初始同步计算及必要资源/UI 初始化后才成功。零尺寸容器延后绘制但不阻塞创建；异步公式状态另行通知。失败或收到取消信号时清理半成品并释放容器占用 |
| 地址                               | 行列从 0 开始；范围结束位置包含在内；公开 API 使用稳定 `sheetId`，不把数组位置当作工作表身份                                                                         |
| `setCellValue(target, value)`      | 是同名命令的便捷入口；普通字符串按文本处理，公式用 `{ formula: "=..." }` 显式表达；不隐式切换活动工作表                                                              |
| `execute(id, params)`              | 返回 Promise，按实例排队；成功表示数据提交及本次同步计算完成，异步公式另发状态事件；渲染可在下一帧发生                                                               |
| `load(input)`                      | 原子替换工作簿并清空历史；失败保留旧工作簿。加载前取消或隔离旧任务，旧结果不能写回新工作簿；新命令在加载结束前返回 `INSTANCE_BUSY`                                   |
| `getSnapshot()`                    | 同步获得最近已提交版本的可序列化副本，不能暴露内部引用；不自动提交正在输入但未确认的编辑值                                                                           |
| `on(name, handler)`                | 返回幂等取消订阅函数；事件发生在提交之后，不暴露可变 Store。监听器异常单独报告，不回滚已提交操作                                                                     |
| `setOptions(patch)`                | 目标支持动态更新主题、只读、UI 显示和已加载能力的开关；不接受更换容器或用配置悄悄替换数据                                                                            |
| `resize()`                         | 提供手动入口，并由 ResizeObserver 辅助触发；零尺寸时延后绘制，恢复可见后重排，不重新创建实例                                                                         |
| `destroy()`                        | 同步、幂等地断开资源和取消任务；销毁后的工作簿操作返回或抛出 `INSTANCE_DESTROYED`                                                                                    |

同一实例的修改按调用顺序处理；事件处理器触发的写入排到当前事务之后。`load()` 等待已开始的提交结束再进入加载状态；加载中的快照读取返回旧的已提交版本。销毁应使未完成的创建、加载和插件注册 Promise 以取消错误结束，不能永久悬挂。

`options.signal` 绑定本次实例生命周期：创建期间取消会拒绝创建，创建成功后取消等同于销毁。语言代码由 SDK 显式映射到旧实现（例如 `zh-CN` 对应 `zh`），不直接透传未经验证的配置值。默认能力、可更新配置和不支持的语言均需在类型及接入文档中列明。

错误应有稳定 `code`、可读 `message` 和必要的 `details`，至少区分无效参数、容器占用、单实例限制、未启用功能、只读、无效快照、加载中和已销毁。API 不以弹窗或 `undefined` 代替失败结果。旧 hook 与新事件建立显式映射，不能把一次操作的内部刷新次数当作业务事件次数。

### 4.2 命令、撤销重做与只读

工具栏、右键菜单、快捷键、插件及外部 API 的工作簿修改最终都进入同一个命令系统。首批覆盖单元格编辑、粘贴、行列操作、格式、合并、排序、筛选和工作表操作。

一次用户操作是一个事务，例如粘贴 1,000 个单元格只产生一个历史记录和一次聚合变更事件。命令先校验参数、能力及只读限制，再提交、计算并通知；失败不得留下部分修改。撤销/重做复用相同数据与计算管线，不能同时写入两套历史栈。

迁移期用适配器接管旧 `jfundo/jfredo`，按操作类型逐项替换。只迁移部分命令时须列出剩余直接写 Store 的入口；所有 P0 修改入口迁移完成前，不宣称统一权限和事务已经覆盖全表格。

`readonly` 禁止用户和公开编辑命令修改工作簿，允许选择、复制和查询；宿主的显式 `load()` 是替换文档，允许用于展示新数据，并发出 `source: "load"` 事件。隐藏按钮只改变 UI；禁用功能则同时限制命令、菜单和快捷键，且不能删除已有数据。基础公式计算是核心依赖，初期不作为可随意关闭的功能。

## 5. 数据兼容与持久化

首轮沿用 Luckysheet 工作表结构，不同时重写单元格模型。新快照先为旧数据增加版本化外壳；这是可演进的持久化契约，不等于承诺所有内部字段永远稳定。

```ts
type WorkbookInput =
  | { format: "luckysheet"; sheets: LegacyWorksheet[] }
  | { format: "snapshot"; snapshot: SpreadsheetSnapshot };

interface SpreadsheetSnapshot {
  schemaVersion: 1;
  dataFormat: "luckysheet";
  workbook: {
    sheets: LegacyWorksheet[]; // 复用旧结构，字段清单由兼容夹具确定
  };
  extensions: Record<string, { version: number; data: JsonValue }>;
}
```

`LegacyWorksheet` 和 `JsonValue` 的具体类型由首轮契约补齐。转换器建立旧 `index` 与公开 `sheetId` 的稳定映射，并将必要映射持久化到版本化的兼容元数据中，保证重新加载、工作表重排或重命名后身份不变；数字/字符串 ID 冲突、重复 ID 和引用修复必须有确定规则及测试。

持久化要求：

- 明确 `celldata` 与运行时二维 `data` 的输入优先级、标准输出形态，以及值 `v`、公式 `f`、显示值 `m`、格式 `ct` 的语义，不能把显示文本当作原值保存。
- 兼容夹具覆盖多工作表、跨表公式、合并、冻结、隐藏行列、条件格式、验证、批注、图片、图表和透视表元数据，检验“旧输入 → 新实例 → 快照 → 新实例”语义一致。
- 快照仅保存文档数据。DOM、函数、事件、网络凭据、连接、运行时缓存及撤销栈不进入快照；旧 `toJson()` 中混合的初始化选项需明确分离。
- 未识别但可序列化的扩展数据保留原字段或命名空间副本。缺少插件时显示能力提示；对会破坏未知引用的删行、删表等操作进行阻止或明确警告，不能声称仅保留原始 JSON 就实现了无损编辑。
- 校验版本、数据形状、引用、尺寸和资源限制；未知未来版本拒绝加载，不猜测转换。未来迁移提供逐版本转换函数和往返夹具。
- 字体、图片等外部资源建立独立资源解析/保存接口；普通 JSON 快照不自动成为包含外部文件的离线归档。

XLSX 导入导出属于文件插件，使用上述文档契约转换。每个文件插件公开支持的特性、缺失项和转换告警，不能用“支持 Excel”代替具体兼容矩阵。

## 6. 插件、主题与框架接入

### 6.1 插件契约与按需加载

保留已有功能并先建立模块边界；将功能改为可选插件之前，必须先识别公式、历史、渲染与数据格式上的依赖。

| 分类         | 能力                                                                | 交付规则                                       |
| ------------ | ------------------------------------------------------------------- | ---------------------------------------------- |
| 核心必选     | 模型、渲染、选区、编辑、公式、基础格式、合并、行列/工作表操作、历史 | 首个可嵌入版本提供                             |
| 默认标准能力 | 冻结、筛选、排序                                                    | P0，默认发行包保留，不能因为拆插件而推迟可用性 |
| 可选标准能力 | 条件格式、验证、批注、图片、自定义公式注册                          | 先保留兼容能力，再逐项完善插件契约和测试       |
| 高级能力     | 图表、透视表、XLSX 导入导出、打印、协同                             | 独立里程碑；数据保留先于编辑能力重构           |

```ts
interface SpreadsheetPlugin {
  id: string;
  version: string;
  sdkApiVersion: string;
  requires?: string[];
  setup(context: PluginContext): void | Promise<void>;
}
```

`PluginContext` 只公开实例查询、命令、事件、UI 扩展点、文档扩展数据和资源登记能力。插件通过资源登记函数提交释放回调；不得直接访问 Store 或扫描宿主页。

`registerPlugin(plugin)` 返回 `Promise<Disposable>`。注册时检查版本、重复 ID、依赖及循环依赖；每实例单独调用 `setup()`，定义对象不保存实例状态。初始化失败撤销本次注册的 UI、命令和资源，已有插件继续工作。初期只允许无依赖者的插件卸载，销毁实例时按依赖逆序释放全部插件；异步注册也受实例取消信号控制。

初期 `setup()` 仅声明和注册能力，不直接修改工作簿；需要数据迁移时，准备完成后通过独立事务执行，避免插件初始化失败却留下文档修改。资源登记器在已取消时立即释放迟到的资源，插件自身也必须响应取消，不能在卸载后继续挂载 UI。

用一个小型示例插件验证命令注册、工具栏扩展、数据保存和资源释放，再迁移图表。高级插件可以复用兼容的开源实现，但所需源码、构建方法、依赖版本及许可记录必须可追溯；不把 CDN 脚本注入作为默认安装方式。

功能开关只控制已安装能力，不能证明减少包体。按需加载要通过独立入口、动态导入和实际产物分析验证：没有导入图表插件的应用，不应下载图表及其框架依赖。

协同插件还需要文档身份、服务器协议、权限校验、冲突处理、离线重连和本地撤销策略。统一命令系统只是基础，不能将命令广播等同于可靠协同；该部分另做专项设计。

### 6.2 主题和自定义 UI

样式限定在 SDK 根节点和所属弹层，沿用可控的 `luckysheet-` 前缀逐步收敛即可，不必先重命名所有类。审计第三方 CSS、字体名和动画名等全局资源。

主题令牌同时驱动 DOM 和 Canvas：颜色、字体、边框、选区等集中定义。只改 CSS Variables 不会自动改变 Canvas 绘制结果；主题变更需更新渲染配置并重绘。两个实例的主题和语言必须可独立设置。

```css
.ls-root,
.ls-overlay-root {
  --ls-color-primary: #1677ff;
  --ls-background: #ffffff;
  --ls-border-color: #e5e7eb;
  --ls-font-family: Arial, sans-serif;
}
```

内置工具栏、公式栏、工作表栏和状态栏支持显示配置；工具栏、菜单提供稳定的 action/context 扩展接口，由框架层映射为插槽或渲染函数。扩展 UI 通过命令执行操作，使用订阅获得禁用态和选区状态，无需访问内部 DOM。

初期采用根节点作用域；Shadow DOM 可作为后续独立验证项。验收同时检查宿主样式干扰表格、表格样式影响宿主这两个方向，以及弹层焦点、键盘操作和基础无障碍名称。

### 6.3 框架适配与发布

适配层只负责实例生命周期、配置更新、事件映射、尺寸变化及公开实例引用。默认使用“初始数据 + 显式 load + 变更事件”的模式，不对整个工作簿深度监听，也不因每次组件渲染重建表格。

Vue 要验证异步创建期间卸载、路由切换、重复挂载和 KeepAlive 恢复；React 要验证 effect 清理与重复执行、回调更新和 ref；Angular 验证组件销毁与变更检测集成；Web Component 验证属性/属性对象映射、连接/断开和重新挂载。每个适配包列出实测框架及版本，不能凭一个包装文件宣称同时支持全部版本。

新模块入口不访问顶层 DOM、不注入全局 jQuery。过渡期可保留内部 jQuery，但必须显式导入、隔离插件注册及状态；只调用 `noConflict()` 不足以证明第三方插件已隔离。UMD/IIFE 兼容包单独发布或提供独立入口，明确其全局变量约定。

先交付 ESM、类型声明、明确的 CSS/字体资源入口和正确的 `exports`；需要 CJS 时再提供真实产物及测试。适配层把 Vue、React、Angular 声明为 peer dependencies，核心包不因此带入框架。`sideEffects` 必须准确保留 CSS 和必要注册，不能为缩小包体直接全部设为 `false`。

发布验收使用安装包创建原生及框架样例，检查入口、类型、CSS、字体路径、子路径部署、离线资源和服务端安全导入。需要提前修正构建入口时可以小范围调整，不应把基础发布正确性拖到“最后升级构建工具”。

## 7. 质量基线与验收场景

### 7.1 功能优先级

| 优先级 | 场景                                                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------------------------------------ |
| P0     | 编辑与中文输入法、数值/文本/日期、基础公式及跨表引用、格式、合并、行列和工作表操作、复制/剪切/粘贴、撤销重做、冻结、筛选、排序 |
| P1     | 条件格式、数据验证、图片、批注、自定义公式、查找替换、填充及复杂格式                                                           |
| P2     | 图表、透视表、XLSX 导入导出、打印和协同                                                                                        |

优先级表示重构验收顺序，不是删除低优先级既有功能的授权。高级能力未迁移时，在兼容入口保留原功能或明确新入口暂不支持；相关文档数据仍按第 5 节保护。

公式基线至少包括相对/绝对引用、跨表引用、插删行列后的引用更新、循环及错误值、文本和日期转换。比较计算结果及文档语义，不只比较截图；已有错误登记为已知缺陷，不能把错误输出确立为正确规范。

测试分为模型/公式单元测试、API 契约测试、浏览器交互测试、截图回归、生命周期和性能测试。工具选型以现有 JS 构建兼容性和维护成本为依据；Playwright 可承担浏览器交互。所有测试结果标记“通过 / 已知失败 / 未覆盖”，没有测试不能记为通过。

### 7.2 首个可嵌入版本的强制验收

1. 同页 A、B 加载不同工作簿，独立编辑、计算、撤销/重做、筛选和排序；复制 A 后粘贴 B 只修改 B，撤销 B 不改变 A。
2. A、B 使用不同语言和主题，同时打开实例弹层；焦点切换后快捷键作用于正确实例，宿主输入框不被拦截。
3. 销毁 A 后，B 的编辑、菜单、公式和网络任务继续工作；A 的延迟请求、公式和插件回调不能更新 B 或重新生成 DOM。
4. 创建失败、创建中取消、加载失败、重复销毁、相同容器重复创建及反复创建/销毁均有自动化用例；建议以 100 次循环检查资源趋势。
5. 弹窗内嵌、隐藏后显示、容器缩放、页面滚动和高像素密度下，选区、输入框和弹层定位正确。
6. 旧数据往返快照后，P0 数据与公式语义一致，未知扩展数据未静默丢弃；无效输入不会破坏当前工作簿。
7. 关闭某项能力后，UI、快捷键和公开命令行为一致；只读禁止编辑，但仍能查看、复制及由宿主加载文档。
8. 使用实际安装包接入，宿主无需预置 `window.luckysheet`、全局 jQuery 或手动排列插件脚本；基础编辑不产生 SDK 隐式外部请求，网络插件及图片等外部资源仅按宿主显式配置加载。

### 7.3 性能与资源预算

先在固定设备、操作系统、浏览器版本、视口和数据夹具上记录基线，再确定正式支持上限。以下是建议起始测试集，不能作为当前性能承诺：

| 夹具                                      | 关注点                                            |
| ----------------------------------------- | ------------------------------------------------- |
| 1,000 行 × 20 列，普通值与格式            | 首次可交互时间、编辑延迟                          |
| 10,000 行 × 50 列，分别构造稀疏和稠密数据 | 初始化、滚动、堆内存及序列化耗时                  |
| 5,000 个公式，含跨表引用和依赖链          | 首次计算、单点编辑后的重算                        |
| 同页 2 个实例，各 1,000 行 × 20 列        | 实例开销、切换和并行异步任务                      |
| 连续创建/销毁 100 次                      | 监听器、观察器、定时器、网络连接及残留 DOM 的增长 |

每项记录预热方式、样本数、中位数和 p95，以及 JS/CSS 原始及压缩体积。初期可将同环境耗时或包体较基线增加超过 10% 设为调查阈值；它是建议的回归报警线，不是尚未测量的产品指标。内存不能要求每次立即回到完全相同的字节数，应结合资源计数和多轮堆快照检查持续增长与无法释放的引用。

首轮根据实际宿主环境登记浏览器支持矩阵及精确测试版本，覆盖 Chromium、Firefox、WebKit 的计划应随结果更新。仓库中的旧 Babel target 不能代替兼容性测试结论。

### 7.4 数据输入和网络能力

外部响应按 JSON 解析并进行结构校验，禁止失败后退回 `new Function()`。超链接、富文本、粘贴 HTML、图片地址和自定义 UI 的输入边界分别测试。认证和存储由宿主服务接口提供，核心编辑路径不依赖固定后端地址。

自定义公式代码来自宿主显式注册，不能从快照恢复可执行函数；远程公式及协同需要显式配置。公式动态求值的替换先补结果基线，再推进解释执行或其他受控实现；严格 CSP 支持列为独立兼容项，未完成前如实标注限制。

## 9. 第一轮可执行任务

第一轮范围为 M0 和 M1，产物是**可验证的实验性兼容入口**。下面的顺序同时给出最先修改的区域，便于拆分提交：

1. 以 `src/core.js`、`src/store/index.js`、`src/global/method.js` 为起点，登记配置、公式、工作表、网络、语言和插件的共享状态及释放责任；记录构建声明与产物差异。
2. 增加测试执行入口和固定夹具，先覆盖编辑、公式、复制粘贴、撤销、合并、筛选/排序、旧数据往返及创建/销毁；同时保存旧入口的已知问题，建立前后对照。
3. 在现有源码下新增独立 SDK/legacy bridge 模块，不先搬迁整仓目录。定义 `WorkbookInput`、Snapshot、错误码和最小实例接口，明确尚未实现的目标 API。
4. 实现创建占用锁、异步取消和幂等销毁；只在实例仍有效时接收初始化结果，创建失败释放锁。半成品资源必须可以清理。
5. 为编辑、加载、快照和事件建立最小适配及契约测试；旧数据转换使用副本，第一轮即验证失败不破坏现有工作簿。
6. 创建原生嵌入示例和双容器验证页面。M1 在页面上验证 B 被明确拒绝且 A 完整保留；M2 再将同一页面升级为两个可同时操作的实例，不把初始页面称为多实例演示。
7. 验证新接口从实际构建产物导入；如暂时仍需 legacy 资源加载，显式标为过渡依赖，并记录达到 M3 自包含入口的剩余工作。

第一轮完成标准：测试入口可重复执行；已承诺的 M1 契约全部通过；原生示例可创建、修改、读取快照和销毁；错误、取消和第二实例拒绝可重现；有清晰的共享状态清单及 M2 迁移顺序。此时仍不宣称已实现实例状态隔离、全套命令、插件生态或生产级多框架 SDK。
