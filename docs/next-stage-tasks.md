# 台账平台下一阶段实施任务

> 本文件为长期 Master Roadmap；当前实施范围与顺序以 [Phase 1 Internal MVP 任务](./phase-1-mvp-tasks.md) 为准。

## 1. 使用方式与边界

依据 [产品设计](./ledger-platform-design.md)、[UI 审计](./luckysheet-ui-audit.md) 和 [既有 SDK 方案](./embeddable-spreadsheet-sdk-plan.md)。以下均是**待实施**任务，本轮未实现生产功能。按依赖逐项执行，不把整张清单一次交给一个“重构全部项目”的任务。

每个叶子编号对应一个独立评审单元，通常是一个提交。带 a/b/c 后缀的任务已拆分；无后缀的同组编号仅用于依赖引用，表示该组全部叶子完成，不能整体作为一次实施任务。编号按领域归组，不是严格执行顺序；按前置依赖推进。若实际修改跨越多个未隔离的旧控制器，先拆出最小接缝任务，不扩大成整模块重写。Core 标记：**否**表示只改新应用/领域/服务或测试；**桥接**表示新增 SDK/legacy bridge 适配，可在引擎内部引用旧 API；**小改**表示需要受回归保护的引擎接缝；任何任务均不授权全面改名、换引擎、改构建体系或直接让业务依赖旧实现。

拟建目录沿用设计中的逻辑模块，尚不存在的目录应在任务实施时创建；后端语言/数据库/首个框架在 T12/T25 的前置选择明确后再落地。可先实现不依赖这些选择的契约、fixture、纯函数和 mock，不把 mock 通过写成真实引擎通过。

### 每项任务的共同完成条件

- 只实现该项承诺的能力；其余命令通过 capability=false 或明确错误处理，不写空成功实现。
- 有与目标匹配的最小测试：纯规则用单元测试，边界用契约测试，焦点/样式/旧引擎行为用浏览器用例；失败路径不能遗漏。
- PR/提交说明写清改变的行为、测试证据、未覆盖内容及 Core 影响。评审检查业务层未导入 Store/controller/DOM，数据是否保持版本一致，失败是否留半成品。
- 可通过撤销该代码提交或功能开关停用；已持久化数据用新增 Revision/前向修复恢复，不删除审计或覆盖已发布定义。数据库采用追加式迁移，旧读路径不能因回滚代码被破坏。
- 不自动发布、接入真实审批或搬运真实台账数据。涉及这些行为时须按任务的实际环境和既有授权执行，设计文档本身不是对外写入指令。
